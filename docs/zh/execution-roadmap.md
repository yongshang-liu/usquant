# 执行路线：保留真实盘，但分阶段验证

你的长期目标是使用真实资金做量化。这个目标保留，当前只开放历史回测，并逐步推进券商模拟。未来意向不等于当前真实订单授权。

## 一、三种模式要分清

| 模式 | 数据与时钟 | 成交来源 | 资金 |
|---|---|---|---|
| 历史回测 | 历史文件、引擎历史时钟 | 引擎的成交、费用和滑点模型 | 虚拟资金 |
| 券商模拟 | 实时行情、实时钟 | 券商模拟账户的订单回报 | 虚拟资金 |
| 真实盘 | 实时行情、实时钟 | 真实券商和市场执行回报 | 真实资金 |

LEAN 的 `live-mode=true` 表示实时运行模式，不足以单独判定是否使用真实资金。必须同时核对具体券商实现、账户和环境参数。Alpaca 的 paper 配置与真实环境不同，不能仅把一个开关改掉就宣称实盘部署完成。

## 二、哪些内容已经保留

- 官方 `vendor/lean` 完整源码及其 Brokerages 接口、实时交易处理器和相关例子，没有因本课只做回测而裁剪。
- 官方 Launcher/config.json 的实时环境示例和 Alpaca 等配置字段保持原样；它们只是参考，不包含我们填入的账户密钥。
- 当前脚本只在生成的临时配置中选择 backtesting，并没有删除官方实时模块。
- 旧实现归档在 legacy，已有 MySQL 和原始数据也保留，供后续按 LEAN 数据契约重新接入。

具体券商适配器可能属于独立官方仓库或发行包；保留核心接口不等于已经安装、授权并验证全部券商。

## 三、进入券商模拟前要亲自完成什么

1. 用已核对的数据重复得到相同回测结果，并解释费用、复权和交易时段。
2. 固定策略版本、数据版本、参数和风险限额。
3. 配置单独的模拟账户，启动时核对它确实是模拟环境，密钥只保存在本机。
4. 检查账户资金、持仓、未完成订单和行情新鲜度，不直接假定账户为空。
5. 先观察一笔小额模拟订单的 Submitted、部分成交或 Filled 等实际回报。
6. 测试撤单、拒单、重复请求、断网、进程退出和重启对账。
7. 做持续运行验证，记录告警、日志和人工停机方法，而不是只看一张收益图。

## 四、进入真实盘前额外验证什么

- 明确真实券商账户、允许交易的证券和真实资金总额。
- 明确单笔金额、单票仓位、总敞口、是否允许杠杆和做空。
- 明确日内损失、最大回撤、价格异常和行情过期的处理方式。
- 启动前确认交易日历、账户状态、订单权限和真实费用模型。
- 验证持仓/订单/现金对账、重复提交防护、异常退出恢复和人工接管。
- 设置独立运行配置，避免模拟和真实账户互相混用；不能把密钥写进 GitHub 或日志。
- 在实施具体资金与策略配置时获得你的明确确认，再先以受限的小规模运行。

这些步骤会逐项实现、逐项说明，不用“已经能回测”替代执行验证。
