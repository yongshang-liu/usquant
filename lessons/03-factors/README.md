# 第三课：指标就绪、因子定义与信号时序

## 学习目标与先修

从一条价格序列构造可解释指标；区分原始数据、指标、因子、方向信号和仓位；检验计算窗口与执行时间。先完成第一课，理解第二课的数据时间边界。完整逐行注释见 [main.py](main.py)。

## 定义先写在结果之前

本课用 SPY 分钟样例，快均线 20 根、慢均线 60 根。方向为 fast > slow，方向转为正时目标 20%，否则空仓。这里的分钟均线只是技术教学例子，不是已获验证的长期选股因子。

SMA(n) 是最近 n 个已完成输入的算术平均。窗口不够时指标未就绪，不能把默认零值当成有效数据。自动注册的 sma 会随 LEAN 数据更新；不要再手动 update 同一条行情，否则会重复计入。

## 运行并寻找证据

```sh
# 只运行固定参数，不在此扫描哪个窗口收益最高。
python3 scripts/run_lean.py factors
```

查看 FACTOR 日志：前 59 根没有就绪信号；第 60 根之后可生成方向。保存当前方向到 pending；下一次有效行情回调先处理 pending，再使用新指标生成下一次方向。这样能明确说明请求使用的是前一次信号。

注意：下一次回调不等于下一根开盘成交。本课仍使用 LEAN 默认订单/成交模型，不能把日志解读成自己保证的开盘价格。最后一根产生的 pending 没有后续行情，不应补一个未来成交。

## 逐行阅读地图

initialize：证券订阅 → 两个官方指标 → pending → previous_signal → 计数器。
on_data：有效行情检查 → 执行上次 pending → 检查慢指标就绪 → 计算当前方向 → 仅在方向改变时排队。
on_end_of_algorithm：确认因子窗口确实就绪过，再输出 COURSE_OK:03。

20% 是交易目标，不是“这个因子有 20% 预测准确率”。previous_signal 防止重复方向触发；pending 防止把新读入的同一信号含混地当成更早可知。

## 实际结果应该怎样解释

本机样例发起 41 张订单，其中 40 张成交、1 张因可用购买力不足而被引擎拒绝，手续费合计 40 美元，期末资产 2460.70 美元。这套短周期规则产生了频繁交易和费用，最终亏损。保留这一结果：它能很好地展示“信号看起来合理”与“扣费后有效”不是同一件事。不通过改窗口、删除费用或缩短亏损区间来美化教学结果。

现金账户还涉及卖出资金的结算与可用购买力，不能把总权益当成随时可再次下单的现金。本课保留拒单并查看订单事件；生产执行须进一步显式处理拒单和资金结算。订单数与成交数必须分开统计。

ready_bars 非零、至少一笔引擎订单和 COURSE_OK:03 代表程序跑通；不代表所有订单都成交，也不代表因子经过统计检验。

## 因子研究还需要什么

正式研究要先写经济假设、观测频率、计算窗口、预测期限和股票池规则。动量可定义为某个过去区间的收益，盈利能力可定义为特定利润与资产口径的比例；定义不唯一，必须记录清楚。财务数据要按披露时间进入样本，不能根据以后修订的数值假装当时已知。

横截面研究还要检查覆盖率、缺失处理、极端值、行业与规模暴露、秩相关 IC、分组收益和换手成本。8 家事后挑选的公司和五天分钟样例不足以完成这些检验。

时间划分在实验前确定。开发集用于设计，验证集用于有限比较，最终测试集不参与反复挑参数。尝试过多少版本也应记录，不能只展示最好的一次。

## 练习与参考答案

1. 把 60 改为 80，最早信号会怎样？至少要多等 20 根有效输入；不是多等 20 个自然日。
2. 把 pending 处理放到新信号赋值之后会怎样？容易把“上一根决策”变成“本根立即决策”，实验时序改变，不能继续沿用旧解释。
3. 20/60 是小时还是分钟？本例输入是分钟，且数据缺失会影响窗口覆盖的实际时间，不能只看数字推断自然时间长度。
4. 为什么不直接每分钟 set_holdings？即便相同目标不一定每次生成成交，也会混淆信号变化、仓位漂移和再平衡需求，应明确规则。
5. 给净利润增长写一个定义。参考：必须说明同季度还是全年、同比基期、负数分母和零分母规则、币种、披露版本与可用时点；仅说“净利润增长率”不够。

## 排错与完成标准

没有交易先检查就绪状态、数据和信号，而非提高仓位。出现未来时间要先定位数据订阅时区和输入可用点。完成标准是能手工复核某一根快慢均线方向、定位它导致的后续请求，并解释费用为何影响结果。下一课：[组合与风控](../04-portfolio-risk/README.md)。
