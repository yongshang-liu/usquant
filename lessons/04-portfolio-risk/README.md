# 第四课：组合构建与风险约束

## 本课要解决什么

单证券信号正确，不代表多证券账户合理。学习 LEAN Framework 如何把“选哪些、看多哪些、配多少、限制什么、如何执行”分离。先修第三课。逐行注释见 [main.py](main.py)。

## 五个组件

Universe 用手工 SPY、IBM 集合声明研究范围；Alpha 用固定向上观点演示接口；Portfolio Construction 把观点转为等权目标；Risk 将每票目标裁剪到约 20%，并检查账户回撤；Execution 根据修正目标请求订单。

固定向上观点只是教具，不是“两个证券都应该买入”的研究结论。本课不使用事后市值排名或当前存续列表充当历史股票池。

## 运行步骤

```sh
# 启动官方 Framework，而不是旧项目自制组合引擎。
python3 scripts/run_lean.py portfolio
```

查找 COURSE_OK:04。capped 表示实际裁剪过多少次目标，halted 表示是否进入永久停止状态。再看订单与持仓：目标的数量是股数，风险上限由 equity × 20% ÷ price 换算成整股。

## 代码顺序

TeachingRisk 保存已观察的权益峰值，只能用过去和当前的账户值。每次 manage_risk 先检查总资产回撤，再逐条裁剪组合目标。触发回撤后取消观点，并持续返回零仓位目标，避免旧观点把账户重新买回。

阈值 0.3% 是为了五天样例覆盖触发路径，不是正式资金的推荐参数。回撤超过阈值后才观察到，不保证最大实际损失恰好被限制在阈值内。跳空、延迟、费用和成交失败都可能扩大损失。

## 仓位上限的准确含义

本模型约束的是输出目标，不是持续实时地保证持仓市值永远低于 20%。股价变化会使占比漂移；实际执行也可能出现未成交或部分成交。本课整数取整后留下现金，不为了凑满比例而使用杠杆。

本机样例覆盖了目标裁剪和停机后退出，两只证券产生入场与退出订单。保留亏损结果，不为了让图上涨而重置风险峰值。

## 风险矩阵练习

写一张表：单票集中度、总敞口、行业集中度、流动性、隔夜跳空、数据过期、未完成订单、信用/券商风险。分别注明测量字段、触发条件、处理动作和恢复条件。不能只写一个 max_drawdown 就声称有完整风控。

## 练习与参考答案

1. 为什么风控返回 PortfolioTarget，而不直接下单？保持模块职责清楚，让执行层统一处理目标差量和订单。混用两条路径可能重复下单。
2. 将 20% 改为 10%，先预计股数变化。由于整股与价格不同，两票实际权重不会精确相同。
3. 为什么停机后取消观点？旧观点可能未过期，如果后续组合模型仍读取它，会再次产生入场目标。清理观点与持续零仓位约束共同防重入。
4. 回撤用初始资金还是峰值？本课用已观察峰值。与“初始本金损失”是不同定义，必须在报告注明。
5. 停机是否立刻清空真实账户？不保证。这里发出退出目标，成交仍要经过订单与市场机制；真实环境需要对账和人工接管。

## 排错与验收

没有裁剪事件：检查 Alpha 是否生成观点、证券有没有价格、组合模型是否产生目标。停机反复入场：检查状态是否持久保持、观点是否取消、目标是否被执行层覆盖。验收需同时读标记、订单和最终持仓，不能只看没有异常退出。下一课：[回测评估](../05-backtest-evaluation/README.md)。
