# 第六课：订单生命周期与券商模拟准备

[课程目录](../../docs/curriculum.md) · [逐行中文代码](main.py) · [上一课](../05-backtest-evaluation/README.md) · [下一课](../07-live-deployment/README.md)

## 学习目标与先修

完成第五课后，学习“想买”“已提交”“已成交”的区别。你将亲自运行限价挂单 → 请求撤单 → 收到撤单确认 → 提交市场单 → 收到成交确认的完整离线路径；再只读查询自己的 Alpaca 模拟账户。这两种实验使用不同的时钟和确认来源，必须分别记录。

## 第一部分：离线状态机

```sh
python3 scripts/run_lean.py orders
```

打开本次 results 目录的 console.log、主结果 JSON 和 order-events 文件。按同一个 order_id 汇总状态，不按日志行数统计订单。预期两张订单：第一张限价单最终 Canceled，第二张市场单最终 Filled；结束标记为 `COURSE_OK:06 canceled_and_filled=True`。订单事件可能比订单多，因为每次状态改变都会产生事件。

### 逐段读代码

1. initialize 设置 2500 美元虚拟现金和现金账户模型，订阅 SPY 分钟数据。ticket 保存操作句柄；其他标志保存本进程的演练状态。
2. on_data 首先检查当前 Slice 中是否真的有该证券。第一次使用当前收盘价的 90% 设置买入限价，制造挂单等待路径；这不是投资建议或限价策略。
3. 第三根有效行情只请求一次撤销。`ticket.cancel()` 是请求，最终成功必须等 `on_order_event` 中的 Canceled。
4. 撤单确认后才请求一股市场单。先设置“已请求”标志，再调用订单函数，避免重复回调重发。
5. 最后分别检查撤单和成交确认，缺少任何一条路径都明确失败。

本课的布尔标志只能保证当前进程的简单路径，不能在断电重启后记住券商已有订单。真实环境必须持久化意图标识，再与券商订单和持仓对账。

## 第二部分：连接真正的模拟账户，只读核验

本机 .env 使用 `ALPACA_API_KEY` 与 `ALPACA_SECRET_KEY`，不要把值粘贴到课堂、GitHub 或截图。已有配置可直接运行：

```sh
python3 scripts/paper_preflight.py
```

逐行阅读 [只读客户端](../../scripts/paper_preflight.py)：域名固定为 paper-api.alpaca.markets；只允许账户、交易时钟、持仓和未完成订单四种 GET；禁止重定向；输出脱敏摘要。报告在 `results/paper-preflight/report.json`，不包含账号和密钥。休市不是连接失败；market_open=false 只表示该时刻休市。订单列表恰好 500 条时会标记可能截断，不能认为已经完整对账。

当前这一步已经成功访问模拟账户，但脚本没有提交或撤销券商订单。离线 Canceled/Filled 也不能当成券商模拟成交证明。

## 第三部分：后续 LEAN 券商模拟的实作作业

这一部分提供验收步骤，尚未把券商适配器接入当前断网启动器。参考固定源码中的 `Common/Interfaces/IBrokerage.cs`、`Brokerages/Brokerage.cs`、`Engine/TransactionHandlers/BrokerageTransactionHandler.cs` 和官方 Launcher 配置；Alpaca 的具体适配发行组件需另外核对安装版本。

先建立独立 paper 配置和订单账本，记录 strategy_version、intent_id、broker_order_id、目标数量、累计成交量和最后确认时间。启动时拉取持仓及未完成订单，完成对账前拒绝新委托。用明确的一股模拟订单依次验证提交、成交、撤单；部分成交、拒单、超时、断线和重启路径分别保存证据。最终验收必须来自券商回报，不能只靠本机日志中“已请求”。

## 练习与参考答案

- 问：撤单后马上买入为何可能买多？答：旧单可能在撤单途中成交；必须先核对旧单最终状态及累计成交量，再计算剩余目标。
- 问：部分成交是否等于失败？答：不是，持仓已改变；剩余数量、费用、撤单和组合风险都要基于累计成交量处理。
- 问：请求超时能否直接重发？答：不能。服务器可能已经接收，先通过稳定意图标识和券商查询排除重复。
- 问：重启后 requested=False 可以继续吗？答：不可以，内存标志丢失。先恢复账本并对账。
- 实作：从日志手写两张订单的状态表。答案至少包含限价单 Submitted/Canceled、市场单 Submitted/Filled，并能对应各自订单编号。

## 排错与完成标准

401/403 时在本机检查是否使用模拟密钥，不打印认证头；网络失败只算预检未通过。离线撤单断言失败时先看第一张单是否意外成交，不能删掉断言来让实验“变绿”。完成本课意味着你能解释订单状态机与只读连接，不表示无人值守模拟系统已经验收。
