# 第七课：真实盘架构、部署计划与异常演练

[课程目录](../../docs/curriculum.md) · [逐行中文算法](main.py) · [上一课](../06-paper-orders/README.md) · [下一课](../08-engine-maintenance/README.md)

## 学习目标

把未来真实资金交易需要的控制写成可检查的计划，并在断网历史环境演练“允许下单”和“停机拒绝下单”。当前课程保留真实盘的架构与操作方法，执行入口仍是离线回测；不会生成可执行的实盘配置。先完成第六课，理解券商确认和账户对账。

## 实验一：正常路径与停机路径

```sh
python3 scripts/run_lean.py deployment --parameter scenario=normal
python3 scripts/run_lean.py deployment --parameter scenario=kill
python3 scripts/check_deployment.py
```

normal 预期一张一股历史模拟订单；kill 预期零订单并有被阻止的信号。两者都应出现 `COURSE_OK:07`。零订单在停机实验中是正确结果，不能把“有成交”当成通用成功标准。

### 代码机制

initialize 固定样例、现金模型与 scenario。on_data 依次检查是否有行情、是否停机、行情是否晚于算法时钟或超过两分钟、价格是否有效、一股名义金额是否超过 500 美元与总资产 20% 中较小的值。条件成立只发一笔市场单；结束时按不同情景检查订单计数。每一条自写执行语句都有中文说明。

这里的 kill 是人工故障注入，阻止新订单；不是平仓指令，也没有验证券商停机。停机时盲目清仓可能因行情异常、休市或重复委托造成新风险，生产系统必须明确“停止开仓”“撤销挂单”“减仓/平仓”的独立动作及授权。

## 实验二：逐项阅读部署计划

[计划 JSON](../../configs/deployment-plan.example.json) 是教学输入，**不是 LEAN 配置**。检查器只验证部分关系并列出待办，即使全部勾选仍输出 executable=false。

| 字段 | 含义与本课值 |
|---|---|
| stage | offline-rehearsal，当前仅演练 |
| brokerage | 拟研究的券商 Alpaca；名称不证明适配已安装 |
| paper_trading | true，未来验证先用模拟账户 |
| live_enabled | false，检查器拒绝打开真实执行 |
| total_capital_usd | 2500，规划资金美元数，未从账户转入任何资金 |
| max_order_usd | 500，单笔名义金额上限；生产还要计入未成交委托 |
| max_position_fraction | 0.20，单票目标占总资产上限 |
| max_gross_fraction | 0.60，总绝对敞口上限；不能只看净多空相抵 |
| allow_short / allow_leverage | false，当前学习计划不做空、不杠杆 |
| daily_loss_fraction | 0.03，未来日损阈值；必须明确交易日、起始权益和资金流调整 |
| drawdown_fraction | 0.08，未来峰值回撤阈值；需要持久化峰值 |
| kill_switch | false，计划字段；修改它不会自动停止其他进程 |
| account_reconciled | false，需核对现金、持仓和挂单后由操作者记录 |
| restart_test_passed | false，需用实际重启证据确认 |
| operator_approved | false，待具体上线配置被人工审核；勾选不产生交易授权 |

计划中的日损、总敞口和峰值限制不是全部都在本课小算法中实现；本课运行验证的是行情门禁、单笔限制及故障注入。完整生产风控需要组合级计算、挂单占用、持久化和券商执行集成，不能把文档字段当成已经生效的限制。

## 从实验到真实部署：完整操作流程

1. 冻结策略、数据、代码和镜像版本，完成时间外检验与压力情景；记录无法验证的假设。
2. 在独立模拟账户安装匹配的 LEAN 券商适配，完成第六课联网订单、部分成交和重启对账作业。
3. 运行持续模拟观察，保留市场开闭盘、断网恢复、拒单和人工停机记录。观察时长应覆盖需要验证的事件，不能仅按天数判定可靠。
4. 准备独立真实账户配置，核对账户类型、资金来源、允许证券、单笔/总敞口限制、费用及行情权限。
5. 启动前由人工确认具体策略、真实账户和资金限额。先小规模观察，按预定条件暂停，不自动扩大资金。
6. 每次启动先对账再接收新信号；每笔委托保留可追踪意图；出现不确定状态就暂停新开仓并查询券商。

### 事故处理卡

| 事件 | 首先做什么 | 恢复证据 |
|---|---|---|
| 行情停止或时间倒退 | 暂停新开仓，记录最后有效时间 | 数据恢复且时间、价格检查通过 |
| 提交超时 | 保留意图，查询券商，避免直接重发 | 券商订单状态与本地账本一致 |
| 账户持仓不一致 | 暂停策略，核对人工交易与累计成交 | 现金、持仓、挂单差异解释完成 |
| 进程崩溃 | 重启先恢复账本和持久化风控状态 | 重启不会重复创建订单 |
| 风险阈值触发 | 按已批准规则停止开仓/处理挂单，通知操作者 | 人工确认后按既定规则恢复 |
| 新版本异常 | 停止新版本，保留日志，回滚固定版本 | 旧版本与当前账户重新对账 |

## 练习与答案

- 把计划 live_enabled 改为 true 再运行检查器：应明确拒绝；不能因为“已经填好计划”跳过模拟验证。
- 为什么重启不能重置峰值？那会抹掉已经发生的回撤，让同一风险规则失去一致性。
- 为什么实时模式不等于实盘？实时描述时钟和数据推进，具体资金环境取决于券商、账户与配置。
- 单笔 500、三张未成交单是否只占 500？不是，挂单可能同时成交，预交易敞口必须汇总。

完成标准：两条离线路径通过，能解释全部字段、恢复步骤及当前未实现的生产控制。真实盘仍需独立工程验收与明确授权。
